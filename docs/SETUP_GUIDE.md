# 導入ガイド（LINE ＋ スプレッドシートで始める版）

プログラミング未経験でも進められるように書いています。
**やることの一覧だけ見たいときは [CHECKLIST.md](CHECKLIST.md)** を使ってください（このガイドは各項目のくわしい説明です）。

- X(旧Twitter) はこの版では対象外です。
- Instagram / Facebook / YouTube は、LINE で手応えが出てから追加する想定です（[最後の章](#あとから追加するとき)）。

## 全体の流れ

| STEP | やること | 目安時間 | お金 |
|---|---|---|---|
| 1 | 自分のパソコンで動かす | 30〜60分 | 0円 |
| 2 | あなたの情報を入れて、返信の質を確かめる | 1〜2時間 | Gemini 利用料（少額） |
| 3 | インターネットに公開する（Google Cloud Run） | 30〜60分 | 少額（後述） |
| 4 | LINE をつなぐ | 30〜60分 | 0円〜 |
| 5 | スプレッドシートに記録する | 15分 | 0円 |
| 6 | 運用を始める | 継続 | ー |

### 使うコマンドは4つだけ

| コマンド | いつ使う？ | 何をする？ |
|---|---|---|
| `npm install` | 最初に1回 | 必要な部品をダウンロードする |
| `npm run setup` | キーを入れる・変えるとき | 質問に答えてキーを貼ると、設定ファイル（`.env`）ができる |
| `npm run dev` | 手元で動かすとき | アプリを起動する（http://localhost:3000） |
| `npm run deploy` | 公開・設定の反映 | インターネットに公開する（2回目以降は更新） |

## STEP 1. 自分のパソコンで動かす

### 1-1. Node.js を入れる（初回のみ）
1. https://nodejs.org を開き、**「LTS」** と書かれたボタンからダウンロードしてインストールする。
2. ターミナルを開く。
   - Mac：`⌘ + スペース` →「ターミナル」と入力して開く
   - Windows：スタートメニューで「PowerShell」と入力して開く
3. 次を入力して Enter。`v22.x.x` のような数字が出ればOK（22 以上）。

```bash
node -v
```

### 1-2. コードを持ってきて、部品をインストールする
1. https://github.com/masa360/influencer を開き、緑の **「Code」** ボタン →「**Download ZIP**」でダウンロードして解凍する。
2. ターミナルで `cd `（cd と半角スペース）と入力し、解凍したフォルダをターミナルにドラッグ＆ドロップして Enter。
3. 次を実行する。最後に `added 〇〇 packages` と出ればOK。

```bash
npm install
```

### 1-3. Gemini の API キーを取る
1. https://aistudio.google.com/apikey を開き、Google アカウントでログインする。
2. 「APIキーを作成」を押して、表示されたキーをコピーする。

### 1-4. 初期設定ウィザードを実行する

```bash
npm run setup
```

画面の質問に答えるだけです。
- **合言葉（ADMIN_TOKEN）は自動で作られます。** 画面に表示される英数字は、あとでアプリに聞かれたときに使います（`.env` にも保存されています）。
- 「キーを貼り付けて Enter」と出たら、1-3 でコピーしたキーを貼り付けて Enter。
  - キーが本当に使えるか、アプリが使う AI モデルが利用できるかまで自動で確認します。モデルが使えない場合は、使えるモデルに自動で切り替えます。
- LINE の質問は、今は **何も入れずに Enter** で飛ばしてOK（STEP 4 で設定します）。

> ⚠️ `.env` は合言葉や鍵が入った大事なファイルです。人に送ったり、ネットに上げたりしないでください（GitHub やサーバーへのアップロード対象からは自動で外してあります）。

### 1-5. 起動する

```bash
npm run dev
```

ターミナルに **設定チェック** が表示されます。`❌` があれば、その内容に従って直してください（多くは `npm run setup` のやり直しで直ります）。

```
Server running on http://localhost:3000
[setup] ✅ GEMINI_API_KEY: 設定済み
[setup] ✅ ADMIN_TOKEN: 設定済み
[setup] ・ LINE: 未設定（LINE連携を使うときに設定）
```

ブラウザで http://localhost:3000 を開いて、画面が出れば STEP 1 は完了です。
止めるときは、ターミナルで `Ctrl + C` を押します。

## STEP 2. あなたの情報を入れて、返信の質を確かめる

1. **「AIキャラ＆ボス設定」タブ** で、あなたの情報を入力する。
   - `【例】` や `〇〇` が残っている項目には、画面上部に ⚠️ の警告が出ます。**すべて書き換えてください。**
   - 「強み・実績」には **本当のことだけ** を書く。AI はここに書いた内容以外の実績・数字は話さないようにしてあります（架空の実績は景品表示法に触れるおそれがあります）。
2. AIキャラのテンプレートを選んで、口調や関係性を調整する。
   - 関係性の欄には「〇〇（あなたの屋号）公式のAI広報」と分かる説明を残してください。
   - 入力した内容はブラウザに自動で保存されます。
3. **「DM誘導シミュレーター」タブ** で、見込み客になりきってメッセージを送り、返信を確かめる。
   - 初回は管理トークンを聞かれます。`npm run setup` で表示された合言葉（`.env` の `ADMIN_TOKEN`）を貼り付けてください。
   - **本番の LINE 自動返信と同じ判定・同じ指示** で返信を作ります。ここで確認した品質が、そのまま本番の品質です。
   - 返信の下に「見込み度」が出ます。本番では、この値が高い人をあなたの LINE に通知します。
   - 「返金」「解約」などを含めると、AI は返信せず「要人間対応」になることも確認できます。
4. 気になる返信があれば、キャラの口調や関係性を直して、もう一度試す。

> 💡 **ステマ規制への配慮**：AIキャラが「無関係の第三者」や「サービスを使ったお客さん」のふりをすると、景品表示法のステマ規制に当たるおそれがあります。この版は、AI が「運営者公式の AI」であることを明かす設計です。SNS のプロフィールにも「〇〇公式のAI広報キャラクター」と書いてください。

## STEP 3. インターネットに公開する（Google Cloud Run）

LINE からメッセージを受け取るには、アプリをインターネット上に置く必要があります。
ここで人の手が必要なのは **3-1〜3-3 の準備だけ** で、公開そのものは `npm run deploy` が自動で行います。

### 3-1. Google Cloud のプロジェクトを作る（初回のみ）
1. https://console.cloud.google.com を開き、画面上部のプロジェクト選択 →「新しいプロジェクト」で作成する。
2. 左上のメニュー →「お支払い」で、そのプロジェクトに **請求先アカウント（クレジットカード）** を設定する。
3. 画面上部に表示される **プロジェクトID**（例：`my-leadgen-123456`）をメモする。

### 3-2. Google Cloud CLI（gcloud）を入れる（初回のみ）
https://cloud.google.com/sdk/docs/install の手順でインストールし、**ターミナルを開き直す**。

### 3-3. ログインしてプロジェクトを選ぶ（初回のみ）

```bash
gcloud auth login
```

ブラウザが開くので、Google アカウントでログインして許可する。続けて（`あなたのプロジェクトID` は 3-1 でメモしたものに置き換える）：

```bash
gcloud config set project あなたのプロジェクトID
```

### 3-4. 公開する

```bash
npm run deploy
```

次のことを全部自動で行います（初回は 5〜10 分）。
- 必要な機能（API）の有効化
- データ保存用の置き場（Cloud Storage のバケット）の作成と、アプリからの読み書きの許可
- `.env` のキーをサーバーに設定（`.env` 自体はアップロードしません）
- アプリの公開と、公開 URL の設定
- 動作確認（`/health`）
- LINE のキーが入っていれば、LINE への Webhook 登録と接続テスト

最後に **「アプリのURL」** と、**残りの手作業** が表示されます。URL をブラウザで開いて画面が出れば成功です。

> 💡 **設定を変えたとき**（`npm run setup` でキーを変えた・アプリのコードを更新した）も、`npm run deploy` をもう一度実行すれば反映されます。データ（設定・受信ログ）は消えません。

> 💰 **費用の目安**：利用がないときはサーバーが自動で止まるので、問い合わせが少ないうちは Cloud Run は無料枠に収まることが多いです。Gemini は使った分だけ課金されます。正確な金額は Google Cloud の料金ページで確認し、コンソールの「お支払い」→「予算とアラート」で **予算アラート** を設定しておくと安心です。

## STEP 4. LINE をつなぐ

### 4-1. LINE公式アカウントを作り、Messaging API をオンにする
1. LINE Official Account Manager（https://manager.line.biz）で公式アカウントを作る（既にあればそれを使う）。
2. 「設定」→「Messaging API」→「**Messaging APIを利用する**」を押す（プロバイダーは新規作成でOK）。

### 4-2. キーを2つコピーして、ウィザードに貼る
1. LINE Developers（https://developers.line.biz/console/）を開き、4-1 で作られたチャネルを選ぶ。
2. 次を実行し、質問に合わせて貼り付ける。

```bash
npm run setup
```

| 質問 | どこからコピー？ |
|---|---|
| チャネルシークレット | 「チャネル基本設定」タブ →「チャネルシークレット」 |
| チャネルアクセストークン（長期） | 「Messaging API設定」タブの一番下 →「発行」して表示された長い文字列 |

公式アカウント名（例：「公式アカウント『〇〇』に接続できました」）が表示されればOK。Gemini の質問は Enter で飛ばせます。

### 4-3. 公開し直す（Webhook は自動で登録される）

```bash
npm run deploy
```

LINE の Webhook URL 登録と接続テストまで自動で行います。最後の表示に従って、次の **手作業** だけ行ってください。
- 「**Webhookの利用**」をオンにするよう表示された場合：LINE Developers →「Messaging API設定」→「Webhookの利用」をオン
- LINE Official Account Manager →「設定」→「応答設定」→ **「応答メッセージ」をオフ**（オンのままだと、定型文と AI の返信が両方送られてしまう）

### 4-4. 手元で作った AIキャラ・ボス設定を、公開したアプリに移す
手元（`npm run dev`）と公開したアプリは、設定の保存場所が別です。次の手順で、入れ直さずに移せます。
1. 手元のアプリ（http://localhost:3000）の「AIキャラ＆ボス設定」タブ →「**設定をコピー**」。
2. 公開したアプリの URL を開き、同じタブ →「**貼り付けて読み込む**」。
3. 公開したアプリの「自動返信（API連携）」タブで管理トークン（`.env` の `ADMIN_TOKEN`）を入力し、「**現在の設定をサーバーに反映**」を押す。
   - 一度反映すれば、別のパソコンやスマホのブラウザで開いたときも「この画面に読み込む」ボタンで呼び出せます。

### 4-5. 自分の LINE を通知先に登録する
1. 同じタブの設定欄にある「**登録コードを発行**」を押す。
2. 表示された「通知登録 123456」のようなメッセージを、**自分の LINE から公式アカウントに送る**（公式アカウントを友だち追加しておく）。
3. 公式アカウントから「✅ 通知先に登録しました」と返事が来て、画面にも自動で反映されれば完了。
   - スタッフも登録したい場合は、同じ手順を繰り返す（最大5人）。

> 💡 通知はLINE公式アカウントの「月間メッセージ通数」にカウントされます。通知が多すぎると感じたら、設定欄の「リード通知のスコア閾値」を上げてください（例：70 → 85）。

## STEP 5. スプレッドシートに記録する

届いた問い合わせが **全件**、Google スプレッドシートに1行ずつ記録されます。承認・却下をすると、同じ行の「状態」が更新されます。

1. Google スプレッドシートを新しく作る（名前は自由。例：「問い合わせ記録」）。
2. アプリの「自動返信」タブ → 設定欄の「**GASコードをコピー**」を押す（合言葉は入力済み）。
3. スプレッドシートのメニュー「**拡張機能**」→「**Apps Script**」を開き、最初から入っているコードをすべて消して貼り付け、💾（保存）を押す。
4. 右上の「**デプロイ**」→「**新しいデプロイ**」を押す。
   - 歯車アイコン →「ウェブアプリ」を選ぶ
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
   - 「デプロイ」を押し、「アクセスを承認」→ 自分のアカウントを選ぶ
   - 「Google で確認されていません」と出たら「詳細」→「（プロジェクト名）に移動」→「許可」
5. 表示された「**ウェブアプリのURL**」（`https://script.google.com/macros/s/…/exec`）をコピーする。
6. アプリの「**記録用Webhook URL（GAS）**」に貼って「**設定を保存**」を押す（合言葉はアプリが自動で付けます）。
7. 「**LINE通知・スプレッドシートにテスト送信**」を押し、✅ が2つ出ればOK。
   - 自分の LINE に「【テスト通知】」が届き、スプレッドシートの「受信ログ」シートにテスト行が増えます（確認したらテスト行は消してOK）。

> ⚠️ 「アクセスできるユーザー：全員」でも、合言葉が合わないリクエストは記録されません。ウェブアプリの URL は人に教えないでください。

## STEP 6. 運用を始める

1. 「自動返信」タブの LINE のカードで「**下書き（承認制）**」を選び、「**設定を保存**」。
2. 画面上部の「**自動返信を開始する**」を押す。
3. 自分のスマホから公式アカウントにメッセージを送り、受信ログに返信案が出ることを確認 →「**この内容で送信**」で届けば完成🎉

運用のコツ：
- **最初の1〜2週間は「下書き」** のまま、返信を毎日確認する。問題がなければ「全自動」に切り替える。
- おかしな返信が出たら、画面上部の「**緊急停止する**」ですぐ止められる。
- 「返金」「解約」「クレーム」などを含むメッセージは、AI が返信せず「要人間対応」になり、あなたの LINE に通知が届く。
- Gemini の利用上限・障害などで **返信エラー** が起きたときも、あなたの LINE に通知される（同じ障害では30分に1回まで）。
- 公式アカウントをグループに招待しても、グループ内の発言には反応しない（1対1のトークだけが対象）。
- LINE の料金：すぐに返す「応答メッセージ」は無料。下書きを承認してあとから送る場合は「プッシュメッセージ」になり、月間無料通数にカウントされる。

### （任意）自分のサイトにチャットを設置する
1. 「LP / HP」カードを開き、「許可するサイトのURL」に自分のサイトの URL（例：`https://www.example.com`）を入れて保存する。
2. 表示された `<script ...>` の1行を、サイトの HTML（`</body>` の直前）に貼る。
   - WordPress なら、ヘッダー/フッター用のプラグインで貼れる。
3. LP / HP のモードを「下書き」→ 様子を見て「全自動」に。

## 困ったときは

| 症状 | 原因と対処 |
|---|---|
| `npm install` でエラー | Node.js のバージョンが古い可能性。`node -v` で 22 以上か確認する |
| `npm run setup` で「APIキーが正しくない」 | Google AI Studio でキーをコピーし直して、もう一度 `npm run setup` |
| 起動時に `[setup] ❌` | その項目がないと動かない。メッセージの通りに `npm run setup` で直す |
| 画面で「管理トークンが正しくありません」 | `.env` の `ADMIN_TOKEN` の値をそのまま貼る（前後に空白が入っていないか確認） |
| `npm run deploy` で「gcloud が見つかりません」 | Google Cloud CLI をインストールし、ターミナルを開き直す |
| `npm run deploy` で「ログインしていません」「プロジェクトが選ばれていません」 | STEP 3-3 のコマンドを実行する |
| `npm run deploy` で「API を有効化できません」 | プロジェクトに請求先アカウント（課金）が設定されているか確認する |
| `npm run deploy` のビルドで権限エラー | 会社の Google Workspace などで権限が制限されている可能性。Google Cloud コンソールの「IAM」で、自分が「オーナー」か確認する |
| LINE の接続テストが失敗 | `npm run setup` のチャネルシークレットが正しいか確認し、`npm run deploy` をやり直す |
| LINE で返信が来ない | 「自動返信を開始する」を押したか、LINE のモードが「オフ」でないか、受信ログに「エラー」が出ていないか確認する |
| LINE で定型文と AI の返信が両方届く | LINE Official Account Manager の「応答メッセージ」をオフにする |
| 通知先の登録で「コードが違います」「期限切れ」 | 画面で「登録コードを発行」を押し直し、表示された文面を10分以内にそのまま送る |
| LINE 通知が届かない | 自分の LINE で公式アカウントを友だち追加しているか、月間メッセージ通数の上限に達していないか確認する |
| テスト送信で「GAS側でエラー: secret_not_set」 | GitHub のファイルではなく、アプリの「GASコードをコピー」で取得したコードを貼り直す |
| テスト送信で「GAS側でエラー: invalid_key」 | アプリの「GASコードをコピー」で取得したコードを貼り直し、Apps Script で「デプロイを管理」→ 新バージョンで更新する |
| テスト送信で「想定外の応答」 | GAS のデプロイで「アクセスできるユーザー：全員」になっているか、URL が `/exec` で終わっているか確認する |
| アプリが動いているか確認したい | `https://（アプリのURL）/health` を開き、`{"ok":true}` と出れば動いている |
| 再デプロイしたら設定が消えた | Cloud Run のログに `[setup] ⚠️ データ保存先 … が永続ボリュームではありません` と出ていないか確認する（`npm run deploy` なら自動で設定される） |

## あとから追加するとき

- **Instagram / Facebook**：Meta for Developers でアプリを作り、App Review（審査）を通す必要があります。審査に数週間かかることがあるので、早めに申請だけ進めておくのがおすすめです。必要な環境変数は README の「チャンネル別の接続手順」を参照し、`.env` に追記して `npm run deploy` で反映します。
- **YouTube**：Google Cloud で OAuth を設定し、リフレッシュトークンを取得します。コメントを定期的に確認する仕組みなので、Cloud Run を常時起動（`--min-instances 1`、費用が増える）にする必要があります。
- **X**：有料 API プランが前提のため、この版では外しています。

### 上級者向け：手動でデプロイする場合
`npm run deploy` が内部で実行しているのは、おおむね次のコマンドです（バケット名・URL などは自動で決まります）。

```bash
gcloud run deploy leadgen-agent --source . --region asia-northeast1 --allow-unauthenticated --max-instances 1 --no-cpu-throttling --execution-environment gen2 --env-vars-file env.yaml --add-volume name=data,type=cloud-storage,bucket=プロジェクトID-leadgen-data --add-volume-mount volume=data,mount-path=/data
```

- `--max-instances 1`：このアプリはサーバー1台で動く前提（2台以上だとデータが食い違う）
- `--no-cpu-throttling`：LINE に「受け取りました」と返したあとも、AI が返信を作り続けられるようにする
- `--add-volume …`：データを Cloud Storage に保存し、再起動しても消えないようにする
