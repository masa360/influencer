# 導入代行ガイド（あなた＝提供する側向け）

お客様ごとにサーバーを1台ずつ用意して、キーを設定して引き渡す「導入代行」のやり方です。
1社の導入は、慣れれば **30〜60分** が目安です（お客様のキーが手元にそろっている場合）。

> 関連ドキュメント
> - お客様に最初に記入してもらう → [ONBOARDING_SHEET.md](ONBOARDING_SHEET.md)
> - お客様に渡す運用の手引 → [CUSTOMER_GUIDE.md](CUSTOMER_GUIDE.md)
> - お客様と結ぶ利用条件のひな形 → [TERMS_TEMPLATE.md](TERMS_TEMPLATE.md)
> - 自分用に動かす手順 → [SETUP_GUIDE.md](SETUP_GUIDE.md)

## 0. 仕組み（1社1サーバー）

```
  あなたのパソコン（このリポジトリ）
   ├─ customers/acme.env   … acme社の鍵（秘密）  ─┐
   ├─ customers/beta.env   … beta社の鍵（秘密）  ─┤  npm run deploy 会社名
   └─ （コードは全社共通）                          │
                                                   ▼
   Cloud Run: leadgen-acme  ←→ acme社のLINE・スプレッドシート・保存データ
   Cloud Run: leadgen-beta  ←→ beta社のLINE・スプレッドシート・保存データ
```

- お客様ごとに **サーバー・保存データ・管理トークン・鍵がすべて別** です（データが混ざりません）。
- コードは全社共通。機能を直したら、`npm run deploy all` で全社に反映できます。
- `customers/` フォルダは **GitHub にも、サーバーにも上がりません**（自動で除外済み）。

### コマンド
| コマンド | 内容 |
|---|---|
| `npm run setup 会社名` | お客様の鍵を入れる（`customers/会社名.env` ができる）。会社名は小文字の英数字とハイフンだけ（例：`acme`, `tanaka-office`） |
| `npm run deploy 会社名` | そのお客様のサーバーを公開／更新 |
| `npm run deploy all` | 登録済みの全社を順番に更新（1社失敗しても残りは続ける。最後に一覧表示） |
| `npm run customers` | 登録済みのお客様の一覧（URL・プロジェクト・最終公開日） |

## 1. サーバーをどこに置く？（先に決める）

| | A. あなたの Google Cloud に置く | B. お客様の Google Cloud に置く |
|---|---|---|
| お客様の手間 | 少ない（キーを渡すだけ） | 多い（プロジェクト作成・課金設定・あなたへの権限付与） |
| サーバー代の請求先 | あなた（下の「費用の目安」参照。お客様に請求するか決める） | お客様 |
| データの置き場所 | **あなたの管理下**（あなたが個人情報を「預かる側」になる） | お客様の管理下 |
| 解約・引き継ぎ | あなたがデータを削除／書き出す | お客様がそのまま使い続けられる |
| おすすめ | 最初の数社。パソコンが苦手なお客様 | 自分で管理できるお客様、データを渡したくないお客様 |

> ⚠️ **A の場合、あなたはお客様の見込み客のメッセージを保存・管理する立場**になります。利用条件に「データの取り扱い」を必ず書いてください（[TERMS_TEMPLATE.md](TERMS_TEMPLATE.md)）。

B の場合は、お客様のプロジェクトで、あなたのGoogleアカウントに **「オーナー」権限**（コンソールの「IAM」→「追加」）を付けてもらいます。作業が終わったら外してもらえます。

## 2. お客様ごとの導入手順

### ① 事前ヒアリング（お客様の作業）
[ONBOARDING_SHEET.md](ONBOARDING_SHEET.md) を渡して、記入してもらいます。次が手に入ります。
- ボス情報（お名前・肩書き・**本当の**実績・ターゲット・誘導先）
- AIキャラの希望（口調・関係性）
- LINE公式アカウントの有無、通知を受け取る担当者
- SNSのプロフィールに「〇〇公式のAI広報」と書くことへの同意

### ② お客様のキーを受け取る（お客様の作業）
お客様自身のアカウントで、次の3つを取ってもらいます。**キーはお客様のものを使い、あなたのキーを使い回さない**でください（料金がお客様に請求され、お客様のデータが混ざりません）。
| キー | 取り方 |
|---|---|
| Gemini の API キー | https://aistudio.google.com/apikey |
| LINE のチャネルシークレット | LINE Developers →「チャネル基本設定」 |
| LINE のチャネルアクセストークン（長期） | LINE Developers →「Messaging API設定」 |

> ⚠️ **キーは、LINEやメールの本文にそのまま書いて送らない**でください。パスワード管理アプリの共有、使い捨てのメモ共有、画面共有しながらの入力などで受け取ります。
> ⚠️ 個人情報（見込み客のメッセージ）を扱うので、Gemini は **有料プラン（課金を有効にしたプロジェクトのキー）** を使うのがおすすめです。無料枠では、入力内容がGoogleのサービス改善に使われる場合があります（**最新の規約を必ず確認**してください）。

### ③ あなたのパソコンで設定する

```bash
npm run setup 会社名
```

- Gemini のキー、LINE の2つ、公開先プロジェクトID（A なら空欄で Enter、B ならお客様のプロジェクトID）を入力します。
- 管理トークンは自動で作られます（`customers/会社名.env` の `ADMIN_TOKEN`）。

### ④ 公開する

```bash
npm run deploy 会社名
```

- 初回は 5〜10 分。LINE の Webhook 登録と接続テストまで自動です。
- 最後に表示される「残りの手作業」に従います（LINEの「Webhookの利用」オン、「応答メッセージ」オフ）。
  - これらは LINE の画面での操作なので、お客様に頼むか、LINE Developers / Official Account Manager に管理者として招待してもらって行います。

### ⑤ アプリの画面で最終設定する
お客様のアプリの URL を開き、管理トークンを入力して、次を行います。
1. 「AIキャラ＆ボス設定」に、ヒアリングシートの内容を入力する（`【例】` `〇〇` が残っていないこと）
   - 入力はお客様ごとのアプリではなく、**自分のパソコン（`npm run dev`）で行って**「設定をコピー」→ お客様のアプリで「貼り付けて読み込む」でも移せます。
2. 「自動返信」タブ →「現在の設定をサーバーに反映」
3. 「登録コードを発行」→ 担当者のLINEから送って通知先に登録
4. スプレッドシート記録を使う場合は、お客様の Google アカウントで [SETUP_GUIDE.md の STEP 5](SETUP_GUIDE.md#step-5-スプレッドシートに記録する)
5. 「DM誘導シミュレーター」と、実際のLINEから自分で送って、返信を一緒に確認する

### ⑥ 引き渡し
- [CUSTOMER_GUIDE.md](CUSTOMER_GUIDE.md) を渡す
- **アプリの URL** と **管理トークン** を渡す（URLとトークンは、別々の連絡手段で）
- 最初の1〜2週間は「下書き（承認制）」のままで運用してもらい、慣れたら「全自動」に
- [TERMS_TEMPLATE.md](TERMS_TEMPLATE.md) をもとにした利用条件に、同意をもらう

## 3. 更新（コードを直したとき）

1. 作業用ブランチで直して、`main` に取り込む（GitHub）。
2. 最新のコードを手元に持ってきて、次を実行する。

```bash
npm run deploy all
```

- お客様のデータ・設定は消えません。
- 1社あたり数分かかります。失敗した会社があれば、最後の一覧に `❌` で出るので、その会社だけ `npm run deploy 会社名` でやり直せます。
- 全社に影響する変更（見た目・返信の判定など）は、先に自分用のサーバーで試してから全社に反映してください。

## 4. 費用の目安（仮。必ず最新の料金ページで確認してください）

**1社・1日あたりの受信メッセージ数ごとの月額**（1ドル150円、米国リージョンの単価、メモリ512MiB、メッセージが散らばって届くと仮定）

| 1日の受信 | サーバーが起きている時間（月） | Cloud Run（月） | Gemini（月）※ |
|---|---|---|---|
| 10通 | 約70時間 | 約0〜50円（無料枠内） | 約170円 |
| 30通 | 約180時間 | 約1,200円 | 約500円 |
| 100通 | 約380時間 | 約3,300円 | 約1,700円 |
| 300通・夜間も届く | 約480〜730時間 | 約4,300〜6,700円 | 約5,000円 |

- **Cloud Run は「最後のアクセスから最大15分は起きたまま」で、起きている間ずっと課金**されます（このアプリは、返事のあとにも裏で処理するため、この設定が必要）。通数が増えるほど高くなります。
- **無料枠は、請求先アカウントごとに1つ**（月約67時間ぶん）です。A（あなたのGoogle Cloudに全社を置く）では全社で合算されるため、10通/日のお客様でも、**5社なら月約2,800円**になります。B（お客様ごとに別のプロジェクト・別の請求先）なら、お客様ごとに無料枠があります。
- ※ Gemini は1通約0.6円（入力2,000・出力600トークンの仮定）。**2027年1月から約2倍**になる予定です（`gemini-3.8-flash` の特別価格が2026年末まで）。「考える」ぶんの出力が多いと、さらに増えます。
- YouTube の自動返信を使うお客様は、サーバーを常時起動する必要があり、**月約6,700円**（1社）かかります。
- 将来、返事を返す前にすべて終わらせる方式に変えれば、Cloud Run の費用はほぼ0円になる見込みです（未実装。YouTube は使えなくなります）。

| 項目 | 誰の負担？ |
|---|---|
| Cloud Run・Cloud Storage | 置き場所による（A：あなた／B：お客様） |
| Gemini（AIの利用料） | **キーの持ち主＝お客様** |
| LINE（公式アカウントのプラン・通数） | お客様。無料プランは**月200通まで**。下書きの承認後の送信と、運営者への通知が数えられる。ライトプランは月額5,000円（税別）。 |

- **上限ガード**（画面の安全設定）：「1日のAI返信の上限」（初期値30件）、「自分へのLINE通知の月間上限」（初期値100通）。お客様の件数に合わせて決めてください。
- あなたの請求（導入費・月額運用費）は、これらとは別に決めます。A の場合は、運用費に Cloud Run の実費を含めるのがおすすめです。
- Google Cloud の **予算アラート** を、お客様ごとのコストが追えるように設定しておくと安心です。

## 5. 解約・終了のとき

**データは自動では消えません。** 利用条件に書いた手順で、次のように対応します。

1. お客様に、受信ログ（スプレッドシート）の控えを渡す。
2. お客様に、Gemini・LINE のキーを **無効化（再発行）** してもらう。
3. サーバーとデータを削除する（**元に戻せません**。お客様の了承を得てから）。

```bash
gcloud run services delete leadgen-会社名 --region asia-northeast1 --project プロジェクトID
```

```bash
gcloud storage rm -r gs://プロジェクトID-leadgen-会社名
```

4. `customers/会社名.env` と `customers/会社名.json` を削除する。
5. LINE の Webhook URL を削除（または別のものに変更）してもらう。
